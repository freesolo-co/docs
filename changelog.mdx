<Update label="July 31, 2026">
  **New · Flash CLI**

## Score held-out suites against a deployed model with `flash env eval`

Put an `evaluations.py` beside your `environment.py` and `flash env eval RUN_ID` scores
those suites against the deployed adapter. Pick one suite with `--suite`, cap the work
with `--max-cases`, and raise `--concurrency` to run cases in parallel. A case that never
reached the model is counted as an error and left out of `pass_rate` and `mean_score`
rather than averaged in as a zero, so a half-broken deployment reads as broken instead of
as a weak model. `flash env test` validates the same suites offline, and `flash env setup`
scaffolds a starter `evaluations.py`. Available in Flash 1.0.34.

**New · Flash CLI**

## `flash models deploy --wait` blocks until the model is servable

Without it, deploy returns while the revision is still queued. With it, the command waits
for the revision to become servable, then exits non-zero if it fails or the wait times
out, so a script can gate on a deploy instead of polling. Defaults to 30 minutes; pass
`--wait 600` for your own budget. Interrupting the wait stops waiting, not the deployment.

**New · Flash CLI**

## `flash env test` can validate the split you actually train on

`--split` picks the dataset split to drive, matching `[environment.params]`, and `--param
KEY=VALUE` passes any other `load_environment()` argument, so the local gate exercises the
data the run will actually use. The gate is also stricter: if every replayed gold answer
scores zero, `flash env test` now fails instead of passing, so a reward function that
cannot recognize its own reference answers is caught before it reaches a GPU.

**Changed · Flash CLI**

## `flash train --dry-run` checks that you can afford the run

The dry run now verifies your org balance against the quote, so an insufficient balance
fails the dry run instead of surfacing when you submit.

</Update>

<Update label="July 28, 2026">
  **Changed · Serving**

## Thinking models split reasoning out of `content`

On the OpenAI-compatible API, a thinking generation now returns its reasoning in
`reasoning_content` and only the answer in `content`, in both JSON and streaming
responses. The `</think>` separator no longer leaks into `content`. Non-thinking
completions are unchanged. `flash models chat` folds the two fields back into one
balanced `<think>...</think>` block, so the CLI still shows the full generation.

**New · Platform**

## Turn your app's live traffic into a training set

Point an OpenAI-compatible client at `https://api.freesolo.co/v1` and Freesolo
records your app's chat completions against a project, then hands them back as a
training dataset with `flash traces export`. Requests are relayed to the provider
you name using a key you supply, and secrets are redacted before anything is
forwarded or stored. See [Tracing](/guides/tracing).

</Update>

<Update label="July 27, 2026">
  **Changed · Flash CLI**

## Every run and environment now belongs to a project

Training configs take a required top-level `project` UUID, and `flash env push` and
`flash env delete` take a required `--project`. Flash validates the project against your
organization before allocating a GPU, so a wrong or missing project fails the submit
instead of starting paid work. Create and find projects with `flash projects create` and
`flash projects list`. Available in Flash 1.0.25.

**Changed · Flash CLI**

## Run and serving commands are grouped under `flash runs` and `flash models`

`flash status`, `log`, `cancel`, and `checkpoints` are now `flash runs status`, `runs log`,
`runs cancel`, and `runs checkpoint`. `flash deploy`, `chat`, `undeploy`, `deployments`, and
`export` are now `flash models deploy`, `models chat`, `models undeploy`,
`models deployments`, and `models export`. Listing base models is `flash models list`.

**New · Platform**

## Deploy and undeploy models from the dashboard

Open a model to see its deployment detail and start or tear down serving from the web app,
without switching to the CLI.

**New · Platform**
